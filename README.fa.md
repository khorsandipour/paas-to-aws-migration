# مهاجرت بدون از دست رفتن داده: یک سامانه‌ی زنده از PaaS به AWS

> نسخه‌ی انگلیسی: [README.md](README.md)

**محرمانگی:** این پروژه تحت قرارداد عدم افشا انجام شده است. نام مشتری، برند، دامنه‌ها، شناسه‌ها، داده‌ها، کد و ابزارهای پروژه منتشر نشده‌اند و متعلق به مشتری هستند. اعداد گرد شده‌اند.

## خلاصه

| مورد | مقدار |
|---|---|
| مشتری | سامانه‌ی تجاری زنده با دو دامنه، یک کد و یک پایگاه داده‌ی مشترک |
| مسیر | از یک محیط `PaaS` با پایگاه داده‌ی محلی به `AWS` |
| قرارداد | قیمت ثابت، چهار مرحله با تأیید مالک |
| مدت | حدود چهار هفته تا پذیرش، به‌علاوه‌ی دو هفته پشتیبانی |
| داده‌ی از دست رفته | صفر |
| تطبیق | حدود ۲۰۰ جدول و حدود ۶۴۰ هزار ردیف، با تطبیق کامل |
| تغییر دامنه‌ها | حدود ۴ دقیقه |
| ۲۴ ساعت اول | صفر خطای سمت سرور |
| نتیجه | هر چهار مرحله پذیرفته و پرداخت شد |

## مشکل اولیه

یک سازوکار بازیابی خودکار در زمان راه‌اندازی، با هر انتشار نسخه، داده‌ی واقعی را با نسخه‌ی پشتیبان قدیمی جایگزین می‌کرد. ثبت‌نام‌ها، تغییر رمزها و سوابق تجاری به عقب برمی‌گشتند و انتشار نسخه عملاً متوقف شده بود.

## مراحل

| مرحله | هدف | نتیجه |
|---|---|---|
| ۱. کشف فقط‌خواندنی | ریشه‌یابی و فهرست کامل، بدون هیچ تغییری | علت ایزوله شد · ۴۵ یافته‌ی رتبه‌بندی‌شده · ۳۶ کار زمان‌بندی‌شده نگاشت شد |
| ۲. ساخت محیط تاریک | زیرساخت تکرارپذیر و شکست‌امن | حذف بازیابی خودکار · پیکربندی بدون مسیر جایگزین · موتور `PDF` ایزوله |
| ۳. تمرین زمان‌دار | اثبات جابه‌جایی، دو بار | هر دو تمرین موفق · ماتریس حفظ داده ۹ از ۹ |
| ۴. جابه‌جایی زنده | انتقال و پایدارسازی | حصارکشی سامانه‌ی قدیم · تطبیق کامل · فعال‌سازی تدریجی ایمیل و کارها · ۲۴ هشدار |

## دغدغه‌های مشتری و پاسخ

| دغدغه | پاسخ |
|---|---|
| تکرار نشدن از دست رفتن داده | انتشار فقط کد را عوض می‌کند و حفظ داده پس از هر انتشار آزموده می‌شود |
| امنیت | هیچ رمزی در گفتگو، کد یا بسته‌ی انتشار نیست · حداقل دسترسی |
| حسابرسی | هر پیام، تصمیم و آزمون با زمان و هش شواهد ثبت شد |
| عدم اجرای هم‌زمان دو سامانه | حصارکشی واقعی پیش از اولین نوشتن |
| اسناد صادرشده | کپی بایت‌به‌بایت و تطبیق هش |
| هزینه | معماری کوچک و اندازه‌گذاری بر اساس اندازه‌گیری |
